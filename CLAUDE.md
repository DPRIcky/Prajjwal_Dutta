# Prajjwal Dutta — Portfolio Website

## What this is
A robotics/autonomy-themed personal portfolio site for Prajjwal Dutta (dual-MS, ASU — Robotics & Autonomous Systems + Manufacturing Engineering). Pure static site: hand-written HTML/CSS/JS, Three.js (r128 via cdnjs CDN) for animated 3D backgrounds. No framework, no build step — every page is self-contained and deployable as-is.

```
site/  (or repo root — this folder maps 1:1 to what gets deployed)
├── index.html                  # home page — hero, about, research, featured work, project grid, skills, contact

```

## Design system — keep every page consistent with this
- **Palette (CSS vars, defined in each page's `:root`)**: `--abyss:#060a14`, `--deep:#0a1226`, `--panel:#0e1830`, `--line:rgba(140,170,220,0.14)`, `--cyan:#4fd8e8` (primary accent), `--amber:#f5a35c` (secondary accent), `--text:#dfe8f4`, `--muted:#8a9ab5`
- **Type**: Space Grotesk (display/headings), IBM Plex Mono (labels, eyebrows, metrics, captions), Sora (body) — loaded from Google Fonts
- **Conventions**: mono uppercase eyebrows with a line rule; numbered section labels (01 /, 02 /...); metric strips (grid of big cyan numbers + tiny mono labels); wireframe-only 3D geometry in cyan/amber/deep-blue; `.reveal` IntersectionObserver scroll animations; `prefers-reduced-motion` respected everywhere; mobile breakpoint at 680–720px reduces 3D object counts/scales
- **3D backgrounds are thematic per page**: index.html has a robotics ecosystem (swarm with live connectivity-graph edges, quadcopter, patrolling rover with LiDAR + dashed waypoint path, blimp with comms-tower uplink, robot arm, scanning grid floor). tube-mpc.html has a literal tube: wireframe tube around a nominal path with an amber vehicle weaving inside it. Every new project page should get its own concept-relevant background variant.

- **Video layer on index.html** — built so a 10-second recruiter scan sees the robots move without clicking into any project page. Three parts, all in the one `CARD VIDEO LAYER` `<script>` block near the bottom of index.html:
  1. **Silent preview loops** — `media/previews/<card-key>.mp4`, one per card that has footage (11 of them, 10–113 KB each, ~470 KB total). **The illustrated `assets/ai/*.jpg` tile is the resting state; the clip is a hover swap, never an unprompted autoplay.** An IntersectionObserver injects and buffers a `.thumb-vid` `<video muted loop playsinline>` when a `[data-vkey]` thumb nears the viewport, then `mouseenter`/`focusin` on the enclosing `.project`/`.gcard` plays it and `mouseleave`/`focusout` stops and rewinds it — hover is bound to the whole card so crossing the ▶ badge doesn't flicker the clip. The tile fades out underneath while the clip is up (`.vplay img{opacity:0}`) so the two never composite. Touch devices have no hover, so where `(hover: hover) and (pointer: fine)` fails the clip plays while the card is on screen instead. Skipped entirely under `prefers-reduced-motion` or `navigator.connection.saveData`. Regenerate with: `ffmpeg -ss <t> -t <6> -i media/<src>.mp4 -an -vf "crop='min(iw,ih*16/9)':'min(ih,iw*9/16)',scale=480:270:flags=lanczos,fps=18" -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 32 -preset slow -movflags +faststart media/previews/<key>.mp4` (foldable-bat uses a bottom-weighted crop, `crop=iw:iw*9/16:0:ih-iw*9/16`, because the wing sits low in frame).
     **Never eyeball the start time — a preview with no motion in it reads as a broken hover.** Verify with `ffmpeg -i <preview> -vf "select='gt(scene,0.004)',metadata=print:file=-" -an -f null - 2>/dev/null | grep -c lavfi.scene_score`; anything under ~15 moving frames out of 108 is too static to ship. Two traps found the hard way: (a) mean-frame-difference alone picks camera pans and converged-jitter over informative motion, so also eyeball a first/last frame pair; (b) `perception-cylinders.mp4` opens on an "Assignment 1 Perception" title card, so its window starts at t=10.
     Cards whose only footage is a static screen get **no `data-vkey` at all** — micro820-plc is the case (its Lab 3 CCW recording measures 0 moving frames end to end), so it keeps the tile and the ▶ badge but has no hover clip. clf-cbf-qp's MATLAB figure redraws too slowly, so its preview is time-compressed `setpts=PTS/2.5`; that is fine because the source is iteration-stepped, not real-time — do NOT do this to footage where speed is part of the claim.
  2. **`.vbadge` play pill** on each card with footage (`▶ WATCH` / `▶ N CLIPS`), a `<button>` sibling of the thumb `<a>` — never nested inside it.
  3. **Lightbox** (`#lb`) plays the full clips inline on the home page — 22 clips, filmstrip of poster thumbnails, prev/next, ←/→/Esc keys, mute toggle, autoplay-next (on when opened from the hero `#reelBtn` reel, off when opened from a card badge), and a "Full project write-up →" link. The `GROUPS` array is the single source of truth for clip file, poster, title, caption, and the page it links to — keep captions in sync with the project pages' figcaptions, and keep the `cr:1` flag on the three `ses598-landing-trial*` clips (it renders the required Anushka Satapathy credit).
  - When a new project page ships with video, add its clips to `GROUPS`, add `data-vkey` + a `.vbadge` to its index card, generate a preview loop, and bump the reel count in `#reelBtn`.
